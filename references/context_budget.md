# SD Film Context Budget And Size Ledger

## Purpose

本文件是SD Film**自身体量纪律**的唯一权威来源。它只服务Skill维护，不是影视制作Pipeline的一部分：不创建STATE，不写入项目状态，不影响用户可见交付，也不得成为新Prompt字段或Template的依据。

它回答一个问题：**文件长到什么程度会让规则读不到、细节被丢掉。**

**目标是可达性，不是尺寸。** 阈值只是观察可达性的手段——它提示“这个文件的长度值得看一眼它的读取方式”，而不是“这个文件超了配额”。因此越过复核线不被判为违规，也不产生债务，只触发一次结构复核；只有达到物理上限才阻断提交。

## Why Size Is A Correctness Issue

Skill分三层加载：`description`常驻、`SKILL.md`在被调用时整体注入、其余文件按需读取。文件过长时，丢的不是磁盘空间，是**细节**：

- **高频必读文件超长**：规则仍在文件里，但落在中段，遵循率显著下降。门禁型规则因此静默失效——文件没坏，行为坏了。
- **细节被自己的长度淹没**：一份写了六十条的规范，实际被执行的往往是开头几条和结尾几条。中间那些不是错误，只是没被读到——**这就是“丢失细节”的真正机制**。
- **检索成本随文件数上升**：找不到应该读哪个文件时，结果是漏读、错读或跳步，而不是报错。
- **同一事实双写**：长文件更难逐项比对，改动只同步一处即产生冲突。

因此本纪律检查的是**规则能否被读到**，不是磁盘占用，也不是写作风格。

## Metric

**主度量是 UTF-8 字节数，不是行数。**

模型的上下文成本按 token／字符计算，不按行。本库Markdown空行占比在31%–57%之间，用行数会把体量高估近一倍，并系统性地漏判段落密集的文件。实测教训：一个395行的文件实为57 KB（全库第4），而一个2330行的文件实为33 KB（中等）——按行数排名会把这两者判反。

行数只作为`SKILL.md`的辅助约束，不作为其他文件的阈值。

## Budget Tiers

| Tier | 阈值 | 性质 | 要求 |
|---|---|---|---|
| Entry | `SKILL.md` ≤ 12 KB 且 ≤ 120 行；实际写入余量以`scripts/validate_sd_film.py`的**8000 字节**为准 | 强制 | 只保留身份、版本、入口、主路由、全局不变量与索引；不得复制细粒度规则、算法或Template字段 |
| 复核线 Review Line | 单文件 ≤ 50 KB | **提示，不阻断** | 越过时复核“使用它的时候会读到全部吗”；确认用不到全部，就拆分它或给出读取入口，并登记在下方Size Index |
| 上限 Ceiling | 单文件 ≤ 100 KB | **强制，不可豁免** | 达到即视为读不完，必须先拆分再提交 |

复核线不是配额，也不是质量评级。越过它只说明这个文件的长度值得确认一下读取方式，**不说明它有问题**。

## File Classes

越过复核线的文件需要归入以下一类。类别决定“能不能留着不拆”，也决定索引里必须写什么：

| Class | 含义 | 处置 |
|---|---|---|
| `COMPOSITE` | 合集型：由并列的独立小节组成，任何一次使用只需要其中一两节 | **应拆**。拆开后每节才能被独立读到；登记只是拆分前的过渡，不得长期保留 |
| `INTEGRAL` | 整体型：由一条连贯的推理链或流程组成，使用时必须整块读完 | 允许留在复核线以上；但必须在Size Index写明**按章节读的入口**，不写入口视同未登记 |
| `NON_RUNTIME` | 非运行时文档，不参与运行时读取 | **不在本纪律管辖内**：没有任何Workflow会读取它，因此不存在“读不完而丢规则”的风险。不登记、不计入复核线；文件自身仍须声明为非运行时文件 |

判定方法：看小节之间是否互相依赖。小节可独立成立 → `COMPOSITE`；缺一节就读不懂整条链 → `INTEGRAL`。**只看体量不看结构会拆错文件**：整体型文件拆开后，单次使用反而要读更多文件。

## Size Index

越过复核线的文件登记在此。**它是读取入口索引，不是债务清单**：记录“这个文件厚，用的时候从哪几节进”，不记录“欠了多少账”，也不暗示它有什么问题。

- 越过复核线但**未登记**：不阻断提交，只出现在`--report`的提示里，供周期性复核时补齐。
- 登记却**没写读取入口**：Validator失败——索引失去意义就等于没有。
- 已降到复核线以下仍留在此表：Validator失败，防止索引腐化成一份固定名单。
- 指向不存在的文件：Validator失败。

## 可达性纪律

体量只是可达性的一个信号。以下三条是**直接**防止细节丢失的要求，优先于任何阈值：

1. **单一 owner**：每条规则正文只在一处完整定义，其他位置只留路由与不变量。重复的完整副本会让改动只同步一处，另一处静默过期。
2. **无孤儿内容**：写入任何字段、规则或知识时，必须同时确认它有消费者——被某个Workflow列为Resource、被某个Template使用、或被某个上游事实引用。**定义了却无人引用的内容等于已经丢了**：它存在，但没有任何路径会读到它。
3. **读取入口明确**：高频必读的文件必须能回答“什么时候读它、从哪一节读”。答不出来的文件，无论多小都可能被整块跳过。

## Budget Discipline

本文件只拥有**可达性判据与索引**；维护体系的执行顺序、层次与报告格式由`references/maintenance_self_check.md`拥有，不在此重复。

### Write-Time Limits

- **先归位再新增**：默认把内容补进既有owner；只有确认没有合适位置才新增文件。
- **新文件不得一出生就是大文件**：新建Markdown不得超过复核线的60%（**30 KB**）。超过即说明它本应是既有文件的一节，或本身就该再分。
- **变厚必须给出入口**：任何改动使文件越过复核线时，必须在同一次变更内登记它的读取入口，或拆分它。**要求不是“不得越过”，而是“越过时必须说清怎么读”。**
- 宁可拆一个文件，也不要为了凑阈值删掉已确认的规则、字段归属或回归场景。

### Index Upkeep

- **越过必登记**：文件越过复核线时，在同一次变更中登记其Class、实测体量与读取入口。
- **落回必移除**：文件降到复核线以下时，在同一次变更中移除条目。不允许保留已经达标的僵尸条目。
- **索引随体量走**：`Size`列必须反映最近一次实测值；实测与登记值差异超过**20%**即视为索引过期，Validator会失败。
- **复审到期必重估**：到达`Review By`时重新判断，要么拆分、要么更新入口与新的复审日期。不得默认续期。
- **拆分必须按编号／职责边界**：拆分后每个文件的编号或命名空间保持连续，并由原文件提供Index；不得为压体量而切断互相依赖的链条。

### Entry Quality

- `INTEGRAL`条目必须写明“按章节读”的入口；不写入口的`INTEGRAL`视同未登记，Validator会失败。
- `COMPOSITE`条目是**待拆队列**，不是长期状态；连续两次复审仍未拆分，按未处理项上报。

## Change Interaction

- 本纪律不构成新增文件的理由。新增或拆分文件时，`references/maintenance_self_check_protocol.md`的`Rule Ownership Check`仍然优先；只有确认现有权威位置不合适才允许新增。
- 本文件的数值与Size Index不与任何其他文件重复：`references/maintenance_self_check_protocol.md`的`Context Budget Check`只引用本文件，不复制阈值。
- 读取顺序、按需读取与复用纪律仍由`rules/resource_loading.md`拥有；本文件不重复定义运行时加载行为。
- 本纪律保护的是**规则能被读到**；它不评价写作风格，也不阻止任何文件因为内容需要而变长——只要求变长时说清怎么读。
