# Atom 1 — Layout And Space｜版面与空间

## Purpose And Owner

本原子拥有 `2d_anime` 档的**取景与空间表达**：在一个没有摄影机的媒介里，景别、人物大小、空间纵深与遮挡如何被"画"出来。

它与实拍的`knowledge/camera_language/lens_language/framing_and_scale.md`、`focal_length_and_perspective.md`与`knowledge/camera_language/composition_language/`互为**对等物**：那些原子用光学量表达取景，本原子用版面量表达同一件事。

边界：不拥有轴线、银幕方向与人物拓扑（归`knowledge/spatial_blocking_layer.md`与 Relational Screen Geometry）；不拥有美学方向（归 STATE-04）。

## Executable Vocabulary｜可执行词汇

| 实拍量（本档禁止写入） | 绘制媒介等效物 | 写进哪个既有字段 |
|---|---|---|
| 景别：全景 / 中景 / 近景 / 特写 | **角色在版面高度上的占比**：全身 / 膝上 / 胸上 / 肩上 / 面部 | `景别` |
| 摄影机距离 | 版面占比 + 角色与背景层的相对尺度差 | `景别`、`构图` |
| 广角夸张 / 长焦压缩 | **前中后景的层数与层间距**：层数少、层间尺度差小=压缩；层数多、近层显著放大=广角 | `构图` |
| 景深虚化 | **分层清晰度分配**：主体层为线稿实边，其余层降级为简化形或无细节色块 | `构图` |
| 前景遮挡 | 前景层压过角色层的**面积与位置** | `构图` |
| 负空间 | **留白**：版面空白作为注意力工具与呼吸位置 | `构图` |
| 画幅（相机画幅） | **交付画幅**（如竖屏 / 横屏）决定版面的长边方向与安全区 | `画幅` |

## Conditions And Anti-Use｜成立条件与反用

- **层数守恒**：一次生成可稳定处理的层数有限。默认前中后三层加角色层；需要更多层时先合并，不要靠在Prompt里堆叠层名来增加纵深。
- **占比即景别**：本档写"景别"就是写占比，不得再解释成"镜头远近"。写成`中景`但没有占比时，模型会自行决定人物大小。
- **遮挡不得盖住身份读点**：面部、发型轮廓、服装识别特征与关键道具不得被前景层压住；遮挡的作用是分配注意力，不是制造层次感。
- **留白必须服务信息**：留白用于停顿、孤立、期待或威胁的画外暗示；无信息的空白只会稀释画面。
- **竖屏安全区**：交付画幅为竖屏时，安全区判据由`knowledge/camera_language/composition_language/vertical_framing.md`唯一拥有（该文件是交付画幅的owner）；本原子只补其在版面上的落法——人物主体与身份读点保持在版面中央纵向带内，不得把关键信息放在最上沿或最下沿。
- **禁止**：把焦段毫米数、光圈、真实景深、摄影机距离、轨道/摇臂/稳定器写进任何字段。它们在绘制媒介里没有对应物。

## Prompt Translation｜Prompt 转译

只使用既有字段，新增字段一律禁止。示例写法：

- `景别：膝上半身，占版面高度约三分之二`
- `构图：前中后三层——前景雨伞压过左下角，中景为角色（线稿实边），后景街道降级为无细节色块；主体右上留白`
- `画幅：9:16 竖版，主体保持在中央纵向带`

分层信息必须写成**可画出来的层**（谁在前、压住什么、哪一层有细节），不得写成"空间层次丰富"这类无执行项的形容。

## Failure Signals｜失败信号

- 画面出现实拍光学痕迹：透视畸变、广角拉长、真实景深虚化、镜头暗角——说明实拍词汇漏进了Prompt。
- 前景遮挡盖住面部或关键道具，身份读点丢失。
- 层数堆叠导致画面糊成一团，或后景细节过多抢走主体注意力。
- 写的是"中景"但人物大小随机，相邻镜头占比不一致。
- 竖屏项目把人物压到边缘或把关键信息放在最上沿/最下沿。
