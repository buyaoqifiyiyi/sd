# Color Foundations

## Core Corrections

- 冷色、暖色、青橙、高饱和、低饱和、暗黑、霓虹、糖果和小清新都不是固定情绪或题材公式。
- 色调不负责新增蓝灯、橙色夕阳、霓虹招牌、火焰或彩色墙面；这些必须来自Lighting、Environment、Prop或FX事实。
- 暗黑色调不等于欠曝或死黑；关键人物、动作、道具与空间锚点仍须可读。
- 高饱和不等于所有颜色同时拉满；优先保持综合色彩主次，避免通道溢出、肤色污染和资产颜色失真。
- 低饱和不等于灰度图；关键身份色、道具线索和肤色差异仍须保留。
- 糖果色通常结合高明度、柔和对比和受控的粉彩/浅色关系，不是简单高饱和。
- “小清新”是综合色彩、曝光、光质、环境洁净度与材质共同结果，不是单一青蓝滤镜。

## Atomic Color Model

每个适用项目或镜头至少确认：

1. Source Basis：已确认光源、时间、天气、环境/服装/道具/FX颜色与材质。
2. Palette Hierarchy：主色、辅助色、强调色及其画面占比和空间来源。
3. Hue Relation：单色、邻近、互补/冷暖分离或受控多色关系。
4. Saturation：综合色彩、人物、背景和强调色各自的饱和度层级。
5. Luminance / Contrast：整体明度、黑位、高光、局部对比与关键细节保护。
6. White Balance / Tint：综合色温和绿色—品红偏色倾向；不将其误写成新光源。
7. Skin / Neutral Protection：肤色、眼白、牙齿、白衣、灰墙和金属等中性色如何保持可信。
8. Material Response：皮肤、织物、玻璃、金属、水面、湿地、烟雾在综合色彩中的反射/吸收结果。
9. Temporal State：起始色态、本镜唯一必要变化、稳定结束色态和下一镜继承。

## Responsibility Boundary

- Lighting拥有光源身份、位置、方向、强度、光质与受光。
- Color拥有综合色彩整理、综合色温/偏色、综合色相结构、饱和度、明度/对比和综合色彩连续性。
- Exposure由Lighting/Cinematography共同约束；Color不能用“暗黑”掩盖欠曝。
- Asset拥有角色发色、肤色、服装、环境与道具的固有颜色；Color只能组织表现，不能重设计。
- Performance拥有表演节拍；冷暖或饱和度不能替代人物可见反应。
- Texture拥有颗粒、锐度、光晕和材质触感；Color不把这些重复定义为色调。

## Palette Structure

- 主色承担大面积环境或共同基调。
- 辅助色建立层次或角色—环境分离。
- 强调色用于已确认人物、道具、FX或实用光源，面积应受控。
- 综合色彩冲突时优先保留资产身份色、肤色、叙事线索和关键动作可读性。
- 用户未提供色值或品牌标准时，不擅自创建Hex、RGB、LUT、胶片库或显示色域参数。

## Skin And Neutral Rule

- 肤色可以接受环境色反射，但须保留人类皮肤的明暗体积和局部综合色彩差异，避免单色涂抹。
- 冷调环境可让阴影偏冷，但不默认把整张脸变蓝；暖调环境同理不把肤色推成橙红。
- 霓虹双色光需要明确两侧光源位置、主次关系和未受光区，避免脸部随机换色。
- 白色和灰色不必绝对中性，但必须成为判断偏色与综合色温是否漂移的稳定锚点。

## Prompt Compiler

- `【主风格】`：写整个生成段共同的主/辅/强调色、饱和度、明度/对比、综合色温/偏色和肤色/中性色保护。
- `【环境一致性】`：写颜色的真实空间来源、固定色彩锚点、材质响应和连续性边界。
- `起始状态`：写当前综合色彩和实用色光的已继承状态。
- `画面描述`：只写人物移动、光源变化或已确认事件导致的一次可见色态变化。
- `人物动作与情绪`：只补充关键表演通道在当前色调下必须可读，不用颜色代替情绪。
- `空间关系`：写主/辅色区域、人物与背景的综合色彩分离、反射/材质来源。
- `道具状态`：只记录已确认发光/变色道具的颜色和变化阶段。
- `镜头结尾状态`与`与下一镜衔接`：写稳定结束色态及继承/断点。
- `【反向提示词】`：按需限制肤色漂移、综合色调闪变、饱和度泵动、黑位压死、高光通道溢出、霓虹换边和资产颜色重写。

最终Prompt不输出CLR编号，也不新增Color/色调字段。

## Prompt Quality Gate

合格色调设计必须回答：颜色从哪里来、如何分层、饱和度和明暗如何组织、肤色与中性色如何保护、材质如何响应、何时变化以及怎样继承。只写“冷色调、电影感”不合格。
