# Seedance 2.5 多模态时间线视频提示词

## Purpose And Ownership

这是仅在 `Target Video Model = Seedance 2.5` 时使用的 STATE-08 最终输出模板。它是Seedance 2.5最终字段、顺序和排版的唯一 owner；`templates/10_video_prompt.md`只拥有Seedance 2.0，`templates/13_minimax_h3_video_prompt.md`只拥有MiniMax H3的最终格式。

设计目标是直接利用2.5的多模态参考、时间戳文本控制、30秒叙事和网页端（显式选择时）的长视频能力：先清楚分配每项参考职责，再给全局叙事与连续性约束，最后用连续时间线驱动可见事件、镜头、动作、台词、音效和状态变化。

此模板不改变Production-Locked Script、Canonical Asset、Director Intent、Spatial Blocking、A/B/C尾帧合同、Voice opt-in或视频Prompt永久无BGM规则。它不声明任何未验证的API字段；Dreamina网页端专有能力必须有`Delivery Surface = DREAMINA_WEB`证据。

## Field Contract

### 时长 / 画幅（正文不写）

本模板没有`时长：`与`画幅：`字段。目标时长由`时间线：`末阶段的末端边界承担，必须在4—30秒内，16—30秒须严格预检PASS；只有`Delivery Surface = DREAMINA_WEB`且用户明确要求长视频时才可到30—180秒网页端时长，且不得因此修改API/常规Clip时长规则。正文同样不得写总片时长、帧率、帧数、帧区间或按秒动作区间。输出分辨率与宽高比是用户在生成时自行选择的平台参数，不进入本Prompt，也不得另设字段声明。

### 多模态参考资产：

默认按2.5的能力边界审计：图片≤30、视频≤10、音频≤10、合计≤50，视频和音频各自总时长≤30秒；实际入口更低时遵从入口。能力上限是默认**容量限制**，不是强制填满额度。每一个实际提交素材必须有真实来源、唯一Primary Role、授权维度和当前Clip收益；无用途、重复或跨世界状态不适用的素材不得列入。纯音频驱动必须明确其只控制动作、口型或节奏中的哪一项。

每一条的引用名固定写作`@图片N：<资产ID>｜<资产名>`（视频 / 音频同理）。环境View在其后以下划线补View Code，例如`ENV-001｜面馆主视图_ENV-01`；同一Asset ID对应多张Canonical Reference图（环境View、State、Costume、Material）时不补View Code或Purpose即视为不合格。`@图片N`是平台上传顺序标记，必须与实际上传顺序一致，且不得省略；冒号后只写中文标签（如`林秀兰角色表`）、只写名称或只写平台附件位都不合格。条目必须能按`references/asset_package.md`的`Final Prompt Correspondence`一对一落到包内真实文件；落不到、或同一Asset ID对应多个文件名时，按该文件的失效与报告规则处理，不得交付。

角色外观、环境结构、道具造型仍优先服从Confirmed Canonical Assets；动作/机位视频、白模和临时草图不得覆盖它们。Final=`REQUIRED`且草图可访问、Signature匹配、预算有位时，写`- @图片N：REF-SKETCH-XX｜<真实文件或受控ID>；用途：实际提交的Clip Blocking / Visual Blocking；锁定 / 保持：仅Position / Facing / Distance / Topology / Axis / Camera / Pose / Gaze / Action Path。`当草图含有占位人偶、朝向标记、追踪色块或版式边框时，该行还必须写明它是**技术参考而非画面内容**：占位标记不是额外人物、道具或装饰，草图的线条、分区、标注与追踪色不得出现在最终画面。它计入图片与合计预算；不可提交时Prompt Pending，不得写成已使用。STATE-07按实际光色漂移风险选择的`Project Color Reference（非资产）`可以作为@图片输入，但唯一Primary Role只能是综合色相 / 明度 / 饱和度 / 强调色占比，且不得控制角色、环境、道具、构图、光源、镜头或最终画风。A/B尾帧和Video Extension的`REF-VIDEO`仍按既有合同写明用途和真实可用状态。

### 参考素材职责与优先级：

此字段让多参考输入可执行，而不是只罗列文件。按素材逐项说明责任，不把同一维度交给冲突的多个参考；需要共同承担时写清主/辅关系。上传顺序只有实际入口要求时才写在本字段，禁止虚构平台参数或内部任务标签。

### 首帧参考 / 尾帧限制：

分别承担当前Clip第一帧和最后稳定帧。A/B/C连续性语义、人物位置/朝向、摄影机、道具、光色与持续声音必须可复核；C不虚构上一Clip尾帧。不得把全局人物身份或重复参考列表再次全文写入这里。

### 主风格：

这是Seedance 2.5独立、无条件的项目视觉入口。最低内容按`knowledge/prompt_compilation/state08_projection.md`的`### 主风格 Minimum Content Rule`执行：建立轮必须写足标签或基线 + 项目内含义、Visual Grammar Baseline的稳定倾向、Aesthetic Decision Lock四项各一次（每项含选择与它排除的可见结果）以及当前Clip的载体；后续连续Clip只保留已锁定锚点与当前Delta，但四锁锚点不得整体消失。先写经确认的项目风格标签或Visual Grammar Baseline，再立刻给出它在当前项目的具体含义，以及当前Clip最有控制价值的可见 / 可听载体，例如真实光源与色彩关系、摄影机介入方式、构图层级、质感或表演尺度——载体数量可少，**不得把本字段压成一句风格句**。风格必须来自已确认Visual Direction / Project Bible、Canonical资产、Director Intent与当前剧情功能的交集；不得用抽象形容词、无依据默认场景包或重复的角色 / 环境设定替代。逐镜动作、空间、时间顺序与End状态不属于本字段。

### 全局叙事与画面设定：

只用一句清楚说明本Clip的主体、地点、事件、主题和核心镜头意图。风格的完整定义只写在`主风格：`；此处不得重复风格载体或用抽象词替代主体、动作、空间或摄影机。

### 全局一致性与执行约束：

写需要贯穿时间线的角色、环境、轴线、光色、关键道具、声音和连续性边界。已由参考资产锁定的内容只做最小确认；当前阶段变化进入对应时间线，不把每段都写成完整角色或场景设定。

### 时间线：

- 2.5的时间线是核心控制层。用严格递进、无重叠的区间，如`[0—3秒]`、`[第3—7秒]`；简单单动作镜头可只使用一个阶段。**末阶段的末端边界必须等于 STATE-07 确认的目标时长**——该相等性由STATE-07/STATE-08的上下文校验承担，因为Prompt正文已不声明`时长：`。
- 阶段数量以Confirmed Clip Production Plan锁定的分镜/阶段单元为准，必须与实际阶段区间数量一致；在时间线首行写明总数声明，例如“本Clip严格只有N个阶段，禁止增加额外阶段、额外镜头或额外场景”，不得为此新增顶级字段。模型可能自行补出计划外镜头或阶段时，`全局限制与反向提示词：`保留同义兜底句。
- 每一阶段完整写画面与镜头、人物动作与情绪、空间与道具、台词、音效和阶段结尾状态。`画面与镜头`必须包含可见事件、机位/构图、主要运镜的起点—触发—路径—终点；不写逐帧参数或工程级精密轨迹。
- **阶段内微节拍推进**：当一个阶段承载连续长镜头内的多个节奏节点时，`画面与镜头`与`人物动作与情绪`必须按微节拍逐点推进，不得写成一段概括。内部密度判据为约0.3—1.2秒一个节点，每点写清该点的机位状态、主体动作、眼与脸、空间与道具变化；该秒数只作内部判据，不作为文字写入Prompt。微节拍只提高既有阶段内部的叙述密度：**不新增阶段、不改变阶段总数声明、不新增字段**，也不因此把时间戳能力扩展到2.0或H3。
- 事件按“开始状态 → 动作启动 → 过程 → 结果”展开；多人明确Primary Performer和反应顺序，动作/道具/空间/轴线连续。转场写清媒介、方向、过程、终点和第一个稳定构图。
- `画面与镜头`或`空间与道具`必须承担背景与环境活动：有可见非主要角色时逐人给出镜内任务、注意对象、时点与强度差异，写明谁先察觉、谁晚半拍、谁完全不看；不得所有人同一时点转向同一目标或同时冻结。环境按地点与时间维持自己的节奏，不等待主人公启动；无人时写清环境动态或有意留白与仅有环境声。背景活动不得穿过主体轮廓、遮挡关键表演或制造错误焦点。
- `阶段结尾状态`是下一阶段的来源；最后一段必须与`尾帧限制：`相容。不得提前发生下一Clip保留的动作。

### 全局限制与反向提示词：

第一句固定为模板中的无BGM禁令。其余只保留当前Clip无法通过正向描述锁死的少量真实风险，例如身份漂移、人物复制、错误换手、轴线翻转或关键道具变形；模型可能自行增加计划外阶段、镜头或场景时，保留一句与时间线总数声明一致的兜底；不得成为事故历史、未来剧情、通用长清单或与全局/时间线重复的文本。

## Dreamina Web Conditional Surface

仅当内部`Delivery Surface = DREAMINA_WEB`时，模板可按用户任务附加到现有字段内容，不能新增顶级字段：

- 30—180秒Long Video：时间线覆盖全时长，分段仍按剧情和状态变化，不为了填满时间而机械切碎。
- Smart / Marked Edit：在相关时间线阶段写`CHANGE`、`PRESERVE`、用户标注区域/锚点和时间点；没有原视频或标注时，不假装已完成标注编辑。
- Green Screen / Viewpoint Edit：在全局一致性与相关时间线阶段明确保留主体、动作、构图和声音，以及目标背景/视角。
- Seamless Transition：只在已有两段用户视频时，在交界时间线阶段写双方保持项、衔接媒介、方向和连接锚点。
- Multi-grid Storyboard：将用户上传多格图的每格职责写入参考素材职责，再用时间线补足每格的可执行镜头与动作；多格图不提升为Canonical资产。

## Output QA

保存为文件时必须运行 `scripts/validate_prompt_package.py <prompt-file> --model seedance-2.5`；该校验器只做确定性断言（字段存在与顺序、阶段递进无重叠、终段位置、无BGM固定句，以及两条内容形态：Canonical参考条目的`<资产ID>｜<资产名>`形态与`主风格`不得保留通用负向清单），未通过不得交付，通过也不替代下列语义检查。参考条目与包内文件的一一对应不在该校验器的断言范围内，必须按`references/asset_package.md`的`Final Prompt Correspondence`单独完成。

- 多模态参考资产、参考素材职责与优先级、首帧参考、尾帧限制、主风格、全局叙事与画面设定、全局一致性与执行约束、时间线、全局限制与反向提示词均存在且非空；正文没有标题行、`时长：`或`画幅：`（标题、目标时长、分辨率与宽高比由STATE-07的Confirmed Clip Production Plan拥有，不入Prompt正文）。
- 每条参考条目均为`@图片N：<资产ID>｜<资产名>`形态，`@图片N`连续且与上传顺序一致；环境View已补View Code；同一Asset ID对应多张Canonical图时必须补View Code或Purpose（如`PROP-001｜花灯_Identity`、`PROP-001｜花灯_State`），**包内文件名的扩展名不进入引用名**；每条都能一对一落到包内真实文件，无孤儿图、无同一Asset ID对应多个文件名。
- `主风格`按`knowledge/prompt_compilation/state08_projection.md`的`### 主风格 Minimum Content Rule`写足（建立轮四块：基线/含义、Visual Grammar Baseline、四项Aesthetic Decision Lock各一次、当前Clip载体），且不保留通用负向清单（`禁止 / 不要 / 避免 / 不做 / 拒绝 / 不得`）——那些约束收束到末尾唯一`反向提示词`。**四锁里"排除了什么可见结果"是必需内容**：它属于Aesthetic Decision Lock本身，不是要搬走的通用负向清单，只有与具体风格判断无关的通用禁止项才移走。四锁在字段内保留维度名（`反差与光比结构` / `色彩对抗关系` / `构图主张` / `视觉母题与变化轨迹`），便于逐项核对；字段完全没有维度名时校验器给出`WARNING`（不阻断交付），部分缺失仍须人工判定；裸`不X`式边界（如"不破败、不阴森"）能改写成正向状态的一律改写。
- 每项实际参考都有唯一Primary Role；计数符合图片≤30、视频≤10、音频≤10、合计≤50、视频/音频各自≤30秒以及实际入口限制；Final=`REQUIRED`时存在可访问、签名匹配且实际提交的`REF-SKETCH-XX @图片N`。
- 时间线严格递进、无重叠、覆盖当前Clip的关键变化，且不超过确认时长；每阶段六项字段完整；时间线首行已声明阶段总数且与实际阶段数量一致，没有计划外阶段或镜头。
- **多阶段一镜到底必须有运镜层次**：相邻阶段在距离 / 角度 / 运动方向 / 速度 / 是否静止上至少一项可指认不同，每段写清起点 → 触发 → 路径 → 终点；通篇"平稳后退—极小弧移—低降—极小幅靠近—极慢后移"这类同一语汇的小幅缓动等于固定机位，只允许作为其中一段且必须由剧情节点触发，至少一次"停住—再启动"或方向 / 幅度变化。上游Clip Movement Plan没有阶段差异时返回STATE-07，不在这里另造。三个阶段以上的时间线若每段都是小幅缓动且无一段写明静止 / 停驻 / 反向 / 幅度变化，校验器给出`WARNING`（不阻断交付，刻意静止是否服务剧情仍由Output QA与用户判定）。
- **运镜必须写出情绪触发者**：每段运镜变化写明是谁的哪个可见表演/情绪事件触发的（抬眼、克制吸气、按灭屏幕、听到震动、抬头、收住的半步），并给出可核对的起止（`中景 → 近景`、`两人距离 → 手与脸`）；整片至少一次由关键情绪节点驱动。只写"固定观察 / 跟随 / 停住"而不写触发者，或全部阶段的运镜只由空间 / 功能（走过门框、进出门、雨声）触发，判定为"没有情绪运镜"，返回Director / STATE-07补。
- **参考覆盖按`rules/02_asset_rules.md`的路由覆盖不变量核对**：风险清单逐项标`已路由`或`文字锁`，不得静默留空；有过反向背景 / 轴线 / 门窗朝向风险时至少覆盖`ENV-01`与`ENV-02`或`ENV-03`；服装与道具的**状态**（敞/合、亮/灭、干/湿）是独立风险，不能只用一张身份图代替。含切场或跨两个空间却只列 `_ENV-01` 时，校验器给出`WARNING`（不阻断交付）。
- 不存在冲突参考、重复的资产长描述、未确认素材、虚构上传/标注/API参数或其他模型能力。
- 角色、环境、空间、道具、表演、镜头与声音连续；不新增剧情，不改写上游确认事实。
- 最后段落只出现一次，且以固定无BGM禁令开头。
