# Rules


不要重新设计人物。


不要改变环境结构。


不要加入额外元素。


首帧必须与本镜头起始状态一致。

战斗、双主体、对峙、对话、追逐、相向运动或来源—目标交互中，首帧优先作为镜头几何锚点：逐项冻结A/B画面左右、高低、前后、身体朝向、视线、距离、摄影机轴线侧，以及攻击/武器/追逐路线/水流/能量的来源—路径—目标。动作必须从该帧直接继续，不能重新摆位；双方相对同框时不得同时完整正脸。

合法首帧或上一段尾帧已经建立关系轴时，文字不得推翻该几何。若目标镜位需要跨轴、交换屏幕左右或改变同框面部关系，只能在Shot Design已授权并提供可理解路径时执行；否则改为Reference-Only兼容边界或返回上游修正。

当本段为G02及以后时，在既有判定中明确A【同镜头连续承接 / Direct】、B【新镜头参考型 / Reference-Only】或C【新镜头且无需尾帧 / Not Required】。A/B均标记`Tail Frame Required = YES`，并在`参考资产：`直接列`REF-TAIL-XX｜CLIP-XX尾帧参考`：A标“同镜头连续承接用途”，B标“空间/站位/景别参考用途”。A在`首帧参考：`逐字写`以 REF-TAIL-XX｜CLIP-XX尾帧参考 为直接承接依据起镜。`并完整锁定；B说明参考尾帧延续站位/朝向/距离/景别/空间/道具或构图逻辑，但当前Clip另起新镜头重新构图，禁止使用A固定句。A/B尾帧尚未提供时仍列名并写“待用户提供/待上传、未确认”，不得伪造路径或声称已上传/已确认；Prompt可交付但实际提交生成前补图。C标记`NO`，不要求截图、不列`REF-TAIL`，依靠Canonical基础资产、Spatial Blocking与文字End State建立新首帧。

当边界为C或Motivated Discontinuity，尤其跨场景时，不得把上一段尾帧伪装成连续首帧或列为下一段参考资产，也不得在本段写`REF-TAIL`名称。只需明确不继承上一Clip画面状态、Canonical基础资产、Spatial Blocking、已确认重建原因以及仍保留的身份/服装/道具后果/情绪锚点。


存在尾帧时，动作过程必须能够在单镜头稳定执行容量内从首帧自然到达尾帧；不得通过换脸、换装、人物瞬移、道具瞬移或环境重构强行匹配。


最终Prompt只在【时长】写一次Confirmed Clip的4—15秒平台生成时长；不得写时间码、总片时长、单分镜时长、按秒分段、帧率或帧数限制。


尾帧只执行已确认动作结果，不得提前包含下一镜才开始的动作。

尾帧还必须保留可复核的A/B左右、朝向、视线、距离、摄影机轴线侧和Connector终点；随机换位、无授权跨轴、双正脸或Connector反向均不得作为下一段连续首帧。


如果首帧、尾帧、上一镜结尾或下一镜开头互相矛盾：

标记Motivated Discontinuity或Unresolved Handoff，不得自动编造中间剧情。

# Output


图生视频执行数据。


如果属于STATE-08：

继续映射到templates/10_video_prompt.md，不直接作为最终Seedance输出。

每个图生视频执行数据只对应一个G生成段和一个Confirmed Clip；Clip可包含1个或多个相邻分镜，单镜Clip独立执行，多镜Clip作为一次连续长镜头执行，逐镜保留首尾边界，只用Clip末镜生成跨Clip尾帧。必须自动判定该尾帧是直接作为下一G段起始帧、仅作为下一G段连续性参考，还是因已确认断点不继承。
