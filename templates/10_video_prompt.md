# STATE-08 / Seedance 视频提示词固定输出契约

## Purpose

本文件是 `STATE-08 Clip-based Video Prompt / Video Generation` 最终 Seedance 视频提示词的唯一格式真源，拥有字段名称、字段顺序、Clip 标题、分镜结构和排版。

这是强制输出契约，不是示例、建议或可选排版。任何 Workflow、Adapter、Knowledge、Rules、旧模板、历史输出习惯或模型自带的 Seedance 排版与本文件冲突时，一律以本文件为最高优先级。

---

## 七项强制完整性规则

1. 所有 Clip 必须使用完全相同的字段结构、字段名称、字段顺序与排版骨架。除分镜数量按当前 Clip 实际内容增加外，不得自行换骨架、改字段名、调整顺序、合并字段、拆分字段或增加字段。
2. 不得因为批量输出、Clip 数量、总篇幅、上下文长度或输出上限而压缩任一 Clip。禁止用表格简写、关键词合集、连续文学段落或其他 Seedance 排版替代本模板。
3. 如果全部 Clip 无法在一次回复中完整容纳，必须自动分批输出。批次边界只能位于两个完整 Clip 之间，不得拆开单个 Clip。每批从下一个尚未交付的 Clip 继续，每个 Clip 仍须包含完整模板。
4. `参考资产：`、`首帧参考：`、`尾帧限制：`是无条件必填字段，任何 Clip 都不得省略、留空、写“同上”或移到其他字段。
5. 每个分镜必须完整重复十个固定字段：`景别：`、`镜头/机位：`、`起始状态：`、`画面描述：`、`人物动作与情绪：`、`空间关系：`、`道具状态：`、`台词：`、`音效：`、`镜头结尾状态：`。不得因内容连续而省略或合并。
6. 任何已有旧模板、旧示例、旧 Workflow、旧 Adapter、旧 Knowledge、旧校验规则或历史对话格式与本模板冲突时，以本文件为最高优先级。冲突内容不得进入最终输出。
7. 输出前必须逐 Clip 执行字段完整性检查；检查失败时只补齐或重排受影响字段，然后重新校验。未通过检查不得输出。

## Clip 独立完整规则

- 一个 Confirmed Clip 对应一个完整的 `# CLIP-X｜标题 Seedance视频提示词` 区块。
- `X` 应沿用 Confirmed Clip Production Plan 中的正式 Clip 编号；推荐使用零填充编号，如 `CLIP-001`、`CLIP-002`。
- 每个 Clip 只包含该 Clip 表中确认的分镜，顺序不得改变、遗漏、重复或跨 Clip 移动。
- 单镜 Clip 仍必须输出完整的分镜字段；多镜 Clip 为每个分镜逐镜完整重复字段。
- 批量授权只改变本轮可输出的 Clip 数量，绝不改变每个 Clip 的模板完整性。
- 默认按现有 STATE-08 单 Clip Checkpoint 交付；用户明确要求全部、一次性、批量或连续输出多个 Clip 时，可以连续输出多个完整 Clip。
- 因长度自动分批不是格式压缩授权。当前批结束时只可在完整 Clip 之后停止，不得以“其余同上”代替后续 Clip。

## 全局字段内容合同

### 时长：

只写 Confirmed Clip Production Plan 中当前 Clip 的平台生成时长，且必须为 4—15 秒。不得写总片时长、逐镜时间码、按秒动作区间、帧率、帧数或帧区间。

### 画幅：

写明已确认的画幅比例、横屏或竖屏、真人或动画媒介属性，以及已确认的非时间轴生成规格。不得为了显得专业而虚构器材或参数。

### 参考资产：

逐项列出当前 Clip 实际使用的 Canonical 角色、环境、道具、FX、Voice/Audio Reference、合法首尾帧与其他确定需要实际投喂的视觉参考图；每项写明资产名称或 ID、用途、锁定对象、真实可用状态和不得改变的特征。真实图片资产必须实际存在、可回查且已确认。已经明确需要用户实际补入的视觉参考图可以作受控占位，但必须写出具体图像对象、实际投喂用途和`待用户补充/待上传、未确认`状态，不得伪造路径、受控ID、上传或确认状态；若缺的是应成为Canonical的正式CHAR / ENV / PROP / FX资产，必须返回STATE-03完成双确认，不得以占位绕过Asset System。既有Voice/Audio Reference继续按独立声音输入合同处理。

列清单前必须通过`knowledge/clip_preflight_check.md`：先把当前Clip分类为视觉连续、剧情连续或主动切场/切世界，再逐分镜确认现实、幻想、耳中玉境或其他已确认World-State。只有当前阶段实际存在、实际出场且状态适用的资产才可列入；完全位于转换后世界的Clip不得保留转换前环境/道具形态，只有当前Clip正在执行合法转换时才可按Pre/Post阶段同时列出两种状态。

随后对每个视觉候选逐项执行最终Visual Input Eligibility QA：`这是不是一张实际会被投喂/引用的视觉资产？`。答案为“否”时必须从本字段移出并按语义归类，不得为了强调而保留。站位说明、不可换边、人物距离、同坐一张板凳、道具数量限制、空间关系说明、行为约束、禁止项与镜头规则分别进入适用的`空间关系`、`起始状态`、`道具状态`、`首帧参考`、`尾帧限制`、`反向提示词`或Spatial Blocking Rules。若对象本身有真实视觉资产，使用正式资产ID与真实引用，例如`PROP-BENCH-01｜双人钢琴凳`；不得使用`板凳参考说明`这类纯文字伪资产。

提交给视频模型的图片参考每Clip硬上限为9张，并按`knowledge/reference_budget.md`执行条件性整合。先删除非当前Clip出场角色、未使用环境/道具/动作图并去重，再计入Direct / Reference-Only所需首尾帧：最终需求≤7不整合；8张且无额外帧需求原则上不整合；9张仅在无未计入连续性需求时允许；已有9张且仍需上一Clip尾帧/当前首帧时按10张处理并至少释放1位；>9张必须整合同类非角色信息，仍超限时按优先级裁剪，最终≤9。

当前Clip每个核心角色必须分别列出各自独立三视图/角色锁定图；多个核心角色不得合并为角色总表，动作/姿势/互动图只负责动作关系，不得替代或覆盖独立角色外貌基准。整合只限环境多视角、道具组、空间关系、动作/互动关系与使用示意等非角色信息。

若独立资产表达更清晰准确且未超限，继续使用独立资产，不因已有总设定图强制替换。总图只有真实存在、已确认且完整覆盖对应零散图时才能列入；不得虚构不存在或未确认的总设定图、空间关系图、动作关系图。每项必须能回查到实际文件/受控ID。

不得写“同上”“沿用前文”“有效内容”或只列文件名。不得引用 Storyboard、多格分镜板、线稿、拼图或 Detailed Shot Design / Clip Plan 截图作为视频生成参考资产。

Preflight必须在既有Previous-Clip Continuity Decision中先明确A【同镜头连续承接 / Direct】、B【新镜头参考型 / Reference-Only】或C【新镜头且无需尾帧 / Not Required】，再检查尾帧是否存在。A/B均标记`Tail Frame Required = YES`并把上一尾帧直接列入本字段，统一命名为`REF-TAIL-XX｜CLIP-XX尾帧参考`：A必须注明“同镜头连续承接用途”；B必须注明“空间/站位/景别参考用途”，推荐写作`REF-TAIL-XX｜CLIP-XX尾帧参考（用于延续上一镜头结尾的角色站位、朝向、景别与空间关系；空间/站位/景别参考用途）`。尚未提供时仍列出该名称和用途，但必须同时标明“待用户提供/待上传、未确认”，不得写假路径或声称已上传/已确认；用户将在实际生成前自行截取并添加。该待补充声明占Projected图片位但不计入已提交图片数，Prompt可以完整交付。C标记`Tail Frame Required = NO`，不要求截图、不列`REF-TAIL`，只依靠Canonical基础资产、Confirmed Spatial Blocking与文字空间规则保持连续性。

任何情况下只要本字段出现`REF-TAIL`，用途类型必须明确为“同镜头连续承接用途”或“空间/站位/景别参考用途”；不得只写资产名、只写“尾帧参考”或混用两种用途。尾帧只作为连续性锚点，不得覆盖角色、环境、道具正式资产。

### 首帧参考：

明确当前 Clip 第一帧来源、Preflight连续性主分类、A/B/C、既有判定中的`Tail Frame Required = YES / NO`以及与上一 Clip 尾帧的唯一承接方式。

- A【同镜头连续承接】必须逐字包含：`以 REF-TAIL-XX｜CLIP-XX尾帧参考 为直接承接依据起镜。` 随后写清上一Clip最后一个镜头在当前Clip继续、目标接近一镜到底，并锁定人物姿态、位置、左右/前后、朝向、视线、人物间距离、动作阶段、构图、景别、机位/轴线侧、环境、天气、光线、道具、情绪与持续声音。
- B【新镜头参考型】必须说明：`参考 REF-TAIL-XX｜CLIP-XX尾帧参考，延续上一镜头结尾的角色站位、朝向、人物距离、景别与空间关系逻辑，但当前Clip另起新镜头重新构图。` 同时写清允许改变的新机位、景别、视角或构图及保持不变的空间/道具事实。B不得使用A类“以该REF-TAIL为直接承接依据起镜”句式，不得误写成同镜头续拍。
- A/B尾帧尚未提供时，本字段须明确“待用户提供/待上传、未确认”，但仍按各自句式完成首帧合同；不得声称图片已存在。Prompt可交付，实际提交生成前补图。
- C【新镜头且无需尾帧】不列`REF-TAIL`、不要求截图；明确换机位/换景别/反打/特写/俯拍仰拍/重构图等新镜头依据，并依靠Active Canonical角色、环境、道具、Confirmed Spatial Blocking与文字空间规则建立首帧。

同时写清人物姿态、位置、左右关系、朝向、视线、距离、摄影机起始位置与轴线侧、景别、构图、环境、天气、道具、动作起始状态、光线和情绪状态。其内容必须与分镜1的“起始状态”一致。

### 尾帧限制：

前置锁定当前 Clip 的最终交付帧。写明人物最终位置、动作、视线与情绪，摄影机最终机位、景别、构图与焦点，道具最终状态，环境、光色和持续声音最终状态，以及下一 Clip 预计如何继承或重建。

尾帧必须稳定、清楚、可冻结、可继承。当前Clip使用上一Clip尾帧时，本字段必须定义本Clip新的结束状态，供实际生成、提取并确认后按当前Clip编号登记为新的`REF-TAIL-XX｜CLIP-XX尾帧参考`；不得沿用上一Clip的尾帧资产名。最后 1 秒不得启动新复杂动作、对白、转头、起步、抬手、接触、道具换手、运镜阶段、场景变化或剧情事件。

### 主风格：

写明当前 Clip 共同遵守的视觉媒介、综合色彩、摄影质感、光线体系、镜头节奏、表演尺度与整体情绪方向。风格参考必须转译为可执行视觉语言，不得只写导演名或空泛质量词。

### 人物一致性：

逐个角色锁定身份、外貌、年龄感、发型、服装、身体比例、当前状态与跨分镜连续性。不得无剧情依据换脸、换装、改变年龄、体型、物种或身份。

同时逐分镜锁定实际可见角色精确数量。剧情规定唯一角色时，必须在本字段正向写明“画面始终只有唯一一只 / 一名X，前景、中景、背景均无第二个同类主体”，并在适用分镜的`画面描述`或`空间关系`再次落实；数量限制不得只写在反向提示词。

### 环境一致性：

锁定地点、时间、天气、空间结构、道路方向、建筑位置、主光方向、固定背景元素、材质与反射、总体运动方向和 180 度轴线。连续分镜不得无理由改变环境或翻转方向。

### 音色特征：

本字段无条件保留，不得因 Voice/Audio Reference 而删除。

- 有适用 Voice/Audio Reference 时，写明“由参考资产中的对应 Voice/Audio Reference 锁定声音身份；不以文字重新定义音高、声线、音域、共鸣、语速或音色质感”，并可补充不改变声音身份的当前情绪、距离、呼吸和同期声空间。
- 无适用 Voice/Audio Reference、但用户先前已显式创建且Active Character Asset中存在Confirmed Voice Profile时，忠实引用其必要特征。
- 有对白但不存在适用Voice/Audio Reference与Confirmed Voice Profile时，写明“未建立独立音色资产；本Clip不创建或推导声音身份，仅执行已确认台词与轻量表演要求”。不得自动调用音色制作模块、返回STATE-03或临时生成Voice Profile。
- 全段无对白时，写明“无对白；本字段保留，听觉叙事由环境声、动作声与呼吸声承担。”

任何分支都必须保留 `音色特征：` 字段名和非空内容。

### 反向提示词：

每个 Clip 最后独立输出，只写本 Clip 真正需要避免的生成错误。默认首句为：

`禁止生成背景音乐、配乐、BGM、主题音乐、氛围音乐，只保留台词、环境声、动作音效和必要的自然声音。`

只有用户明确要求 Seedance 为指定 Clip 生成背景音乐时，才可对该 Clip 省略默认首句；不得把例外扩展到其他 Clip。

剧情存在唯一角色时，本字段还必须禁止该角色被复制、分身、镜像重复、倒影误生成为实体、背景出现第二只/名、相似替身或群体增殖。追逐镜头必须按实际风险禁止双方并排正对镜头、同一景深海报式合影、群像站桩与追逃关系反转。

## 逐分镜字段内容合同

### 景别：

写明镜头开始到结束的景别。景别变化必须与人物动作或摄影机运动一致，不得堆叠无动机变化。

### 镜头/机位：

写明焦段倾向、摄影机位置与高度、朝向、主体距离、对焦对象、主要运镜、运动方向、速度、幅度、轴线侧和最终机位。单镜优先一个主要运镜。

### 起始状态：

明确第一帧来源或要求，人物位置、左右、朝向、视线、动作与情绪阶段，道具持有者及状态，环境、天气、光线、摄影机边界和轴线。连续分镜必须从上一分镜“镜头结尾状态”直接继承；叙事断点必须写明非连续继承与重建依据。

### 画面描述：

按“开始状态 → 动作启动 → 动作过程 → 结束结果”描述可见事件，明确谁先行动、谁后反应、方向、速度、距离、焦点、道具与环境变化，避免文学概括和超出模型容量的动作密度。

现实↔幻想/耳中玉境、地点/时间跳跃、尺度变化或角色/道具形态转换时，必须把已经在Preflight锁定的转场五要素转译到既有字段：本字段明确转换媒介与运动方向/过程；`起始状态`承载起点状态；`道具状态`承载形态转换；`镜头结尾状态`承载终点状态与转场后首个稳定构图。除非用户明确要求，不得只写“金光一闪 / 突然切换”。

### 人物动作与情绪：

把情绪转成可见表演：视线、呼吸、停顿、微表情、手部、肩颈、重心、步伐、距离与行动选择。情绪必须有刺激、反应过程和稳定结果，不得只写抽象标签。

### 空间关系：

明确主体在画面左中右和前中后景的位置、朝向、视线、距离、移动方向、关系轴与摄影机轴线侧。多人关系不得只写“面对彼此”；战斗或来源—目标交互必须写明来源、路径和目标。

追逐默认采用后追前逃：逃者在前方更深景别沿明确方向逃跑，追者在后方较近景别沿同一路线追击；写明谁允许正脸、三分之二侧面、侧背或背身，以及是否允许同一景深。除非用户或Confirmed Shot Design明确要求例外，禁止双方并排、同时完整正脸朝摄影机、同一景深横向站立、海报式合影或群像站桩。

### 道具状态：

写明关键道具名称或 ID、当前World-State、形态、尺寸、材质状态、持有者、左右手、位置、方向、接触关系、是否允许悬浮、形态转换是否已经完成、可见变化过程和结尾状态。现实耳勺与武器化耳勺等不同状态必须按世界阶段切换，不得混用、无过程瞬变、复制成两件或无授权悬浮。无关键道具变化时写“本镜头无关键道具变化”，不得留空或写“同上”。

### 台词：

写明角色、必要的轻量表演方式与准确台词。无台词写“无”。不得擅自增加对白、旁白或解释性独白。

### 音效：

写明环境底声或有理由的有意静默、至少一个与可见动作同步的前景声，以及声音尾部如何保持、切断、淡出或承接。不得留空、写“无”“静音”或只写禁令。

### 镜头结尾状态：

写明最后一帧稳定、可读、可续接的完整状态：人物位置、左右、朝向、视线、动作停留点与情绪，道具最终状态，摄影机最终机位、景别、构图与焦点，环境、光色和持续声音。

本字段同时承载与下一镜的连接语义：明确 Continuous Handoff、Motivated Discontinuity 或 Unresolved Handoff，说明下一镜继承什么、断点是什么或哪些状态待确认；不得另增“与下一镜衔接”字段。连续分镜还必须写明“同一 Clip 连续生成”，并禁止提前执行下一镜动作。

## 输出前字段完整性检查

每个 Clip 在最终输出前必须按以下顺序执行两遍检查：Template Mapping 后一次，交付前一次。

### A. 标题与全局字段

- 标题严格匹配 `# CLIP-X｜标题 Seedance视频提示词`。
- 下列字段各出现且只出现一次，并按顺序排列：`时长：`、`画幅：`、`参考资产：`、`首帧参考：`、`尾帧限制：`、`主风格：`、`人物一致性：`、`环境一致性：`、`音色特征：`。
- `反向提示词：`各出现且只出现一次，并位于当前 Clip 最后。
- `参考资产：`、`首帧参考：`、`尾帧限制：`均非空且位于`主风格：`之前。
- `参考资产：`的Projected图片项总数与已提交图片数均≤9；真实视觉条目只含当前Clip实际使用且真实存在/已确认的资产与合法帧；受控待补视觉条目均写明具体图像对象、实际投喂用途与`待用户补充/待上传、未确认`且未绕过正式资产确认；无重复占位；每个核心角色有各自独立图；只在超限风险触发后整合同类非角色信息。
- 对每个视觉条目逐项提问“这是不是一张实际会被投喂/引用的视觉资产？”且答案均为“是”；任何答案为“否”的文字伪资产已从`参考资产：`移出，并按语义进入`空间关系 / 起始状态 / 道具状态 / 首帧参考 / 尾帧限制 / 反向提示词 / Spatial Blocking Rules`。真实道具图使用正式资产ID，不使用“参考说明”代替。
- 是否明确A/B/C及`Tail Frame Required = YES / NO`；A/B缺图时是否仍直接列统一`REF-TAIL`名称、用途与“待用户提供/待上传、未确认”，且未声称上传或确认；C是否完全未列`REF-TAIL`、未要求截图并采用Canonical资产、Spatial Blocking与文字重建。
- 任何`REF-TAIL`是否明确标注“同镜头连续承接用途”或“空间/站位/景别参考用途”；用途是否与`首帧参考：`一致。
- A的`首帧参考：`是否逐字包含固定直接承接句，并继续锁定姿态、位置、朝向、距离、动作阶段、构图、景别、机位、环境、光线、天气、道具、情绪与持续声音；B是否明确另起新镜头重新构图、写清保持项与允许变化且未使用A固定句；使用上一尾帧的A/B是否都在`尾帧限制：`定义本Clip新的结束状态。
- Clip Preflight是否为PASS：连续性三选一且上一尾帧引用正确；逐分镜World-State与资产一致；角色精确数量与唯一性、追逐/多人空间构图、关键道具状态及适用转场五要素都已进入现有字段；没有新增Preflight字段。
- 不存在方头括号旧章节、独立 `CLIP标题` 字段、条件删除的`音色特征`或任何新增全局字段。

### B. 分镜字段

- 至少存在一个`分镜X`，编号与 Confirmed Clip Production Plan 一致且顺序不变。
- 每个分镜的十个字段各出现且只出现一次，并严格按固定顺序排列。
- 所有字段都有非空内容；允许`台词：无`和说明理由的“不适用”，不允许空值、“同上”“沿用前文”“见上”“略”。
- 不存在第十一个或其他新增分镜字段；下一镜承接语义已经写入`镜头结尾状态：`。

### C. 跨 Clip 与批量完整性

- 每个 Clip 都重新完整输出全部全局字段、全部逐分镜字段和`反向提示词：`。
- 批量输出没有共享字段、合并字段、压缩字段、表格化字段或使用“同上”。
- 长度不足时只在完整 Clip 之后分批，不拆开当前 Clip。
- 每个 Clip 的参考资产、首帧与尾帧形成可复核连续状态链。

### D. 失败处理

出现字段缺失、重复、乱序、改名、合并、额外字段、空值、旧模板或跨 Clip 压缩时，判定该 Clip 输出失败。只修正受影响的格式或映射，然后重新执行完整性检查；不得把失败格式交付给用户。
